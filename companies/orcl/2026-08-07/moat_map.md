# ORCL Moat Map — as_of 2026-08-06

## 1. 两条护城河，深度相差极大

| 护城河 | 所属机器 | 深度 | 方向 | 证据 |
|---|---|---|---|---|
| **M-A 企业数据库转换成本** | 老机器 | **深** | **↓ 收缩中** | Software 收入 FY2026 **−1%**（唯一负增长分部）|
| **M-B Multicloud AI Database** | 桥接 | **中，且在加深** | **↑** | 收入 **+404%**，被称"Oracle 有史以来增长最快的业务" |
| **M-C 规模/速度（先建成先收钱）** | 新机器 | **浅** | ↔ | FY2026 交付 1.2GW；Q1 FY2027 单季"接近 1GW" |
| **M-D 电力与土地先占** | 新机器 | **浅–中** | ↑ | 未取得公司级披露（O）|
| **M-E 融资成本优势** | — | **负护城河** | **↓** | **S&P BBB−**，四大云中最弱 |

## 2. M-A：真护城河，但在被稀释

Oracle 数据库的转换成本是软件业最硬的之一——迁移一个跑了二十年的核心 OLTP 数据库，
风险与成本都极高，这是几十年来 Oracle 定价权的来源。

**但两件事同时在发生：**
1. **它在萎缩**：Software 分部 FY2026 **−1%**，是全公司唯一负增长的分部。
2. **它在被稀释**：Software 占总收入从历史上的绝对主体降到 **36.4%**，
   而 Cloud 已达 **50.5%**。**护城河最深的那部分，正在成为公司里越来越小的一块。**

> 这是一个容易被误读的地方：**"Oracle 有护城河"是真的，
> 但"买 Oracle 就是买那条护城河"已经不再是真的**——
> 你的边际资本 100% 流向了 M-C（浅护城河）。

## 3. M-B：本卡里最被低估的一项

**Multicloud AI Database +404%**（[MEDIA] 转述公司公告）是唯一同时满足三条的业务：
- **用得上 M-A 的特许权**（客户要的是 Oracle 数据库，不是通用算力）
- **高毛利**（软件属性）
- **高增长**（+404%）

**它的机制是**：把 Oracle 数据库部署进 AWS/Azure/GCP 的机房里。
客户不必迁移数据库，也不必把工作负载搬到 OCI——**Oracle 把特许权带到客户已经在的地方去收租。**

> 这条路线**不需要 capex**，**不需要押注单一交易对手**，**直接变现最深的那条护城河**。
> 如果 Oracle 的故事是"M-B 驱动"，本卡的裁决会完全不同。
> **但事实是资本全部投向了 M-C。** 这是资本配置的选择，不是能力的限制。
> → **这也是 runner_dissent 里最该被认真对待的多头论据**：M-B 的规模与利润率本轮未取得（OPEN）。

## 4. M-C / M-E：新机器没有护城河，而且有一条负护城河

**M-C（规模与速度）为什么浅：**
- 产出是**可替代的算力小时**。客户可 multi-cloud，转换成本远低于数据库。
- 投入品（NVDA 芯片、HBM、电力、变压器）都由上游定价 → 成本不受控。
- 前三大云（AWS/Azure/GCP）在同一层竞争，且都比 Oracle 大。
- 到期合约 **49% 的客户续约（覆盖 92% 的 GPU）** 是正面数据，
  但按**客户数**看只有一半续约——**留下的是大客户，走掉的是小客户，集中度因此进一步上升。**

**M-E 是负的：**

| 云厂商 | 信用等级（近似）| capex 资金来源 |
|---|---|---|
| MSFT | AAA 级 | 经营现金流 |
| GOOGL | AA 级 | 经营现金流 |
| AMZN | AA 级 | 经营现金流 + 适度债务 |
| **ORCL** | **BBB−（距投机级一档）** | **净发债 $39.2B/年 + ATM + 优先股** |

> **在一个靠资本强度竞争的行业里，资金成本就是护城河。Oracle 在这一项上是四家里最差的，
> 而且差距在扩大（S&P 2026-07-09 降级）。**
> 这不是"暂时的劣势"——它是一个会自我强化的劣势：
> 融资成本更高 → 单位经济更差 → 评级更差 → 融资成本更高。

## 5. Operator 与护城河的关系

Oracle 的 capex 决策由**新管理层**做出（联席 CEO Clayton Magouyrk / Mike Sicilia，
新 CFO Hilary Maxson，Safra Catz 转任执行副董事长——**均为 [MEDIA]，未经一手验证，见 O7**）。

> 一家在**管理层刚刚换代**的时点，做出**押上资产负债表**的战略转向，
> 这在 operator underwriting 上是负分项——不是因为新人不行，
> 而是因为**没有可供检验的资本配置履历**。详见 `operator_underwriting.md`。

## 6. 护城河总评

**M3 利润池/耐久信号：−1**

| 判据 | 评价 |
|---|---|
| 是否占有瓶颈 | ❌ 否（见 `bottleneck_map.md`）→ 不享瓶颈溢价 |
| 最深的护城河（M-A）方向 | ❌ 收缩（−1%）且占比下降 |
| 最有前途的护城河（M-B）| ✅ +404%，但**未被资本优先支持**，且规模未披露 |
| 边际资本投向的护城河（M-C）| ❌ 浅 |
| 融资成本（M-E）| ❌ **负护城河，四大云最弱，且在恶化** |
| 回报的实际方向 | ❌ **合并 ROIC 15.11% → 11.24%** |
| 客户留存（算力口径）| ✅ 92% 的 GPU 续约 |
| 需求真实性 | ✅ GPU 利用率 97.5% |

**结论**：Oracle 有一条真护城河（M-A）和一条被低估的护城河（M-B），
但**它把钱投向了没有护城河的那一层，并且是用最贵的钱投的**。
护城河存在，但**与资本流向不匹配**——这是 M3 给 −1 而非 +1 的全部理由。
