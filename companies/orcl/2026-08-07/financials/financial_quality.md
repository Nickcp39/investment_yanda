## 1. Owner-Earnings 桥：不闭合，而且是**借钱**导致的不闭合

```
FY2026 经营现金流 (OCF)                        $31,977M
  − 资本开支 (capex)                          −$55,663M
  ─────────────────────────────────────────────────────
  = 自由现金流 (FCF)                          −$23,686M   ← 桥断在这里

  拆分尝试（D&A 作维护 capex 代理，最宽松口径）：
    D&A（派生，中等置信）                        $9,315M
    → "维护后"owner earnings = OCF − D&A        $22,662M
    → 增量/增长 capex = 55,663 − 9,315         $46,348M   = 全部 capex 的 83.3%
```

**三个观察：**

1. **增长 capex $46.3B 是 FY2026 归母净利（$16,984M）的 2.7 倍。**
   即使全部视为"未来的利润"，这也是一个把三年利润一次性投出去的赌注。
2. **"维护后 owner earnings $22.7B"是一个宽松到接近虚构的数字。**
   它假设维护 capex = 当期 D&A = $9,315M，而 **D&A 只覆盖当期 capex 的 16.7%**。
   一个在两年内从 $21.5B 涨到 $129.6B 净额的机队，其稳态更新成本必然远高于今天的折旧。
   → 这就是 **OPEN-O5**，与 GOOGL O1 / AMZN O4 是同一个数字。
3. **与 AMZN 卡的关键差异**：AMZN 的桥不闭合是"算不清"（capex 由 OCF 覆盖，只是没剩下）；
   **ORCL 的桥不闭合是"算不清 + 缺口要靠外部融资填"**（capex 是 OCF 的 174%）。
   这是两个不同性质的问题。

## 3. 盈利质量：净利率上升，其余全部下降

| 指标 | FY2024 | FY2025 | **FY2026** | 变动 |
|---|---:|---:|---:|---:|
| **毛利率** | 71.41% | 70.51% | **65.82%** | **−4.69pp** |
| 营业利润率 | 28.99% | 30.80% | 30.59% | −0.21pp |
| **净利率** | 19.76% | 21.68% | **25.37%** | **+3.69pp** ⬆ |
| **ROIC** | 15.77% | 15.11% | **11.24%** | **−3.87pp** |
| ROCE | 13.91% | 14.42% | 10.64% | −3.78pp |
| ROA | 9.94% | 10.04% | 7.72% | −2.32pp |

**FY2026 营业成本 = 67,357 − 44,336 = $23,021M，同比 +36.0%，而收入同比 +17.3%。
成本增速是收入增速的 2.1 倍。**

**净利率为什么反而上升？（拆开看，这是本节最重要的一段）**

```
FY2026 税前利润        $19,554M
  所得税                $2,467M   → 有效税率仅 12.6%
  净利润               $17,087M

  若按 19% 正常化税率:  19,554 × 0.81 = $15,839M   （比实际低 $1,248M）

另：非营业收入（净）    +$3,547M   ← 口径未拆分，8-K 未说明构成（OPEN-O10）
    利息费用            −$4,599M
```

> **结论**：净利率的改善来自 **12.6% 的低有效税率** 与 **$3,547M 的非营业收入**，
> 不来自主营效率。**毛利率、ROIC、ROA、ROCE 四个反映主营效率的指标全部下降。**
> **只看 EPS（+34%）会得到与只看 ROIC（−3.87pp）完全相反的结论。**

**折旧滞后（C11）**

```
D&A（派生）/ capex                = 9,315 / 55,663      = 16.7%
D&A / 平均净 PP&E                 = 9,315 / 93,157      = 10.0%（隐含~10年，含在建工程干扰）
PP&E 净额                          $56,667M → $129,647M  = +128.8%
```

> 当期折旧只覆盖当期投资的**六分之一**。会计上正确（新资产尚未服役），
> 但意味着**今天的报告利润是在向未来借折旧**。
> 当 $129.6B 的 PP&E 全面进入折旧期，D&A 将成倍上升。
> 若按 6 年直线折旧，仅现有净 PP&E 的稳态年折旧就是 **~$21.6B**，是当前 $9.3B 的 **2.3 倍**。
> **⚠ OPEN-O2（blocking）**：Oracle 实际采用的折旧年限本轮未从 10-K 确认，
> 因此上述 6 年只是**情景假设，不是对 Oracle 的指控**。

### 4.3 交易对手信用：这是本卡的 blocking 项

**已知的正面证据（都是真的，不能忽略）：**
- **GPU 利用率 97.5%** —— 已交付的算力在满负荷跑，说明需求不是纸面的。
- **到期合约中 49% 的客户续约，覆盖到期合约下 92% 的 GPU** —— 续约率按算力口径极高。
- **~$75B 是客户预付或客户自带硬件** —— 这部分**先收钱/先收设备**，信用风险最低，
  且直接减少 Oracle 需要自筹的资本。这是 backlog 中质量最高的一层。

**已知的负面结构：**
- **>50% 的 RPO 对手方是一家未上市、自身现金流深度为负、依赖持续外部融资的公司。**
- **该对手方的收入贡献要到 FY2028 才开始** —— 即 Oracle 今天已经在为它承担利息与折旧，
  但还没有从它身上收到一分钱的规模化收入。
- **Moody's 已明确点名 "significant counterparty risk"**；S&P 在 2026-07-09 的降级理由中亦引用集中敞口。
- **期限与信用错配**：Oracle 承担的是**投资级公司债的确定负债**（固定票息、固定到期），
  承接的是**一个未上市公司的八年期承诺**。两侧的确定性完全不对称。

### 4.4 (b) 的答案

> **backlog 只值客户付得起的那部分，而这一部分本轮无法量化。**
> $638B 中，可以确认质量的是 **~$75B 的预付/自带硬件（11.8%）**；
> 剩余 88% 中，超过一半的对手方 Oracle 自己都不点名。
>
> **这不是"风险偏高"，这是"无法定价"。**
> → **OPEN-O1（blocking）**：OpenAI 的收入 run-rate、现金消耗、融资状况、合约可撤销性条款，
> 以及 Oracle 10-K 的客户集中度披露原文。**在 O1 关闭前，base 情景本身的成立与否是未知的。**

## 5. (c) ROI 披露：三项全无 + 一个口径问题

| 应披露项 | Oracle 是否披露 |
|---|---|
| capex ROI hurdle（投资门槛回报率）| **❌ 无** |
| 增量 ROIC（新增 AI 数据中心的回报）| **❌ 无数值；仅 CFO 口头"high 20s"，二手转述** |
| 维护 capex vs 增长 capex 拆分 | **❌ 无** |

**管理层给出的 ROIC 口径（[MEDIA] 转述电话会）：**

```
ROIC = （税后营业利润 + 折旧） ÷ 项目层面的毛投资额
```

**为什么这个口径不能直接采信：**
1. **分子加回折旧** —— 这就不是"回报"，而是"现金流入"。对于一个折旧才覆盖 capex 16.7% 的机队，
   加回折旧的效果目前较小，但随着机队进入折旧期，这个加回项会越来越大，**使指标越来越好看，而实际回报越来越差**。
2. **分母用毛投资** —— 而非平均投入资本。项目层面的毛投资不扣减已折旧部分，
   短期看是保守的，但配合"分子加回折旧"就形成了系统性高估。
3. **口径是"项目层面"** —— 允许挑选表现最好的项目披露，无法与合并报表对账。

**最有力的反证（本卡的核心分析动作）：**

```
管理层称：增量 ROIC "high 20s"
实际观察：合并 ROIC   FY2024 15.77% → FY2025 15.11% → FY2026 11.24%   （−3.87pp）
```

> 若新增的 $55.7B 投资真的赚 25%+，合并 ROIC 应当**上行**。实际是**连续下行且加速**。
> 两者唯一自洽的解释是"新资产尚未满负荷贡献收入"——
> **而这恰恰是整个论题里唯一尚未被证明、且要到 FY2028 才能验证的那一步。**
>
> **可迁移的方法论**：当公司用自定义口径给出一个高回报数字时，
> 不要去辩论那个数字，去看**合并 ROIC 的方向**。方向不可粉饰。
> **这条检验（C6）可以立刻套用到 GOOGL / AMZN / META / MSFT。**
