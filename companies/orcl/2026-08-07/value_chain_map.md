## 2. 资金的流向（FY2026，$M）

```
   债权人 ──── $46,093 发行 ────┐
   优先股股东 ── ~$5,000 ───────┤
   普通股市场 ── $1,243 净发行 ─┤
                                 ▼
                            【 Oracle 】
   老机器（Software/SaaS）─ OCF $31,977 ─┤
                                 │
                                 ├──► capex $55,663 ──► NVDA / 电力 / 建筑商
                                 ├──► 利息 $4,599 ────► 债权人
                                 ├──► 股息 $5,787 ────► 股东
                                 └──► 偿债 $6,942 ────► 债权人
```

> **一个值得停下来看的事实**：FY2026 Oracle 付给**债权人**的现金
> （利息 $4,599M + 偿债 $6,942M = **$11,541M**）
> 已经**接近付给股东的现金（股息 $5,787M）的两倍**。
> 而在 FY2024，Oracle 还在净回购股票。**资本结构的重心在两年内从股东移向了债权人。**

## 3. 客户侧的集中（这是链条上最脆弱的一环）

| 层 | 规模 | 信用可见度 |
|---|---|---|
| **OpenAI** | **>$319B RPO（>50%）** | **❌ 完全不可见（O1）** |
| 另外四个大客户 | 各 >$8B | ❌ 未点名 |
| $75B 预付 / 客户自带硬件 | ~11.8% 的 RPO | ✅ **最高质量层** |
| 传统企业客户（Software/SaaS）| $24.5B + SaaS 年收入 | ✅ 分散、健康 |

> **链条的形状是"沙漏"**：上游是几家有定价权的寡头，下游是一家占一半以上的对手方，
> Oracle 卡在中间最窄的地方，**两头都被挤压，而且中间这段是用债务撑起来的。**

## 4. 与 GOOGL / AMZN / META / MSFT 在链条上的位置差异

| | 上游议价 | 中段资金来源 | 下游客户结构 |
|---|---|---|---|
| **ORCL** | 全部外购 | **外部融资** | **单一对手 >50%** |
| GOOGL | 部分自研（TPU）绕开 NVDA | 经营现金流 | 极分散（广告 + 云）|
| MSFT | 外购 + 部分自研 | 经营现金流 | 分散（企业 + OpenAI 关联但结构不同）|
| META | 外购 | 经营现金流 | **自用**（不对外出租，无交易对手风险）|
| AMZN | 部分自研（Trainium）| 经营现金流 + 债务 | 分散 |

> **META 的对照最有说服力**：META 的 AI capex 是**自用**的——
> 它没有交易对手风险，只有"投资回报"风险。
> **ORCL 同时承担两种风险，而且用杠杆放大了。**
> 这是把 ORCL 的结局外推到那四家时，最必须先做的一次校正。
