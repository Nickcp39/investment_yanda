### (c) Oracle 是否披露 capex ROI hurdle / 增量 ROIC / 维护-增长拆分？

**没有。三项全部没有。**这本身就是发现，而且比 GOOGL/AMZN 更糟——因为 ORCL 的 capex 是**借来的**。

本轮找到的唯一接近披露的是两条**二手转述**：
1. CFO Hilary Maxson 称预期 ROIC 在 **"high 20s"**（[MEDIA]，未从一手 transcript 验证）；
2. 管理层 ROIC 口径 = **（税后营业利润 + 折旧）÷ 项目层面毛投资额**。

**对这两条的处理，是本卡的核心分析动作：**
- 第 2 条**不是标准 ROIC**。分子**加回折旧**、分母用**毛投资**，这更接近"毛投资上的现金收益率"。
  对一个折旧才覆盖当期 capex **16.7%** 的机队来说，这个口径会系统性、大幅高估真实回报。
- 第 1 条与可观测事实**直接矛盾**：若增量投资真赚 25%+，合并 ROIC 应上行；
  **实际是 15.11% → 11.24%（−3.87pp）**。
  唯一自洽的解释是"新资产尚未满负荷贡献收入"——**而这恰恰是尚未被证明的那一步**。

> **可迁移的方法论**：当公司给出一个自定义口径的高回报数字时，
> 不要去辩论那个数字，去**看合并 ROIC 的方向**。方向是不可粉饰的。

### (e) −55.8% 是倍数 de-rating 还是生意减值？用数字分开

| | 2025-09-10（峰值收盘）| 2026-08-06 | 变动 |

**对账：0.3290 × 1.3433 = 0.4420 → −55.80%** ✅ 与股价变动**完全吻合**。

**答案分三层：**
1. **就盈利水平而言，100% 是倍数 de-rating。EPS 不但没减值，还涨了 34%。**
2. **但 de-rating 的原因是盈利质量减值**：毛利率 −4.69pp、ROIC −3.87pp、

> **最重要的一句**：**盈利水平那一关还没考。** OpenAI 的收入自 **FY2028** 才开始。
> 今天的 24.6x P/E 建立在 FY2026 的 EPS 上，而 FY2026 的 EPS 里几乎没有 AI 合约的贡献，

**关键的分流问题（决定 ORCL 的结局能不能外推）：**

> **C3 + C4 + C7 + C12 这一组是"杠杆分支"。GOOGL / META / MSFT 目前不在这条分支上——
> 它们的 capex 由经营现金流自筹，没有 BBB− 的约束。AMZN 介于两者之间（已加杠杆但保障倍数远高）。**
>
> 因此对那四家的正确外推是：
> - **可以外推的**：C5（毛利率）、C6（ROIC 矛盾检验）、C9（好消息换负反应）、C11（折旧滞后）——
>   这些是**估值倍数**的杀手，会造成 de-rating。**GOOGL 的 K-B 已在 🔴 FIRING，M4 已从 −1 走到 −2，走的正是这条路。**
> - **不能无差别外推的**：C1/C2 触发后的时点，以及 bear 情景的深度。
>   ORCL 的 bear 是 **−8.9% 且带 $124B 净债务的永久损失**；
>   GOOGL/META/MSFT 的 bear 是**倍数回归**，不是资本结构破裂。**同样的机制，不同的下限。**
> - **最该盯的单一转换**：**C7（开始发股权融 capex）**。
>   在那之前，"重投资"是故事；在那之后，"稀释"是事实。
>   目前那四家都还没跨过 C7——**跨过的那一天，把这张卡重新读一遍。**

## runner_dissent（诚实地为反面辩护）

**机械结论 WATCH / 0% 很可能是错的，理由有三条，我认为它们比这张卡给出的分量更重：**

1. **需求侧的证据强度被我低估了。** 97.5% 的 GPU 利用率、到期合约 92% 的 GPU 续约、
   Multicloud AI Database +404%、OCI +93%、$75B 的客户**预付与自带硬件**——
   这些不是"承诺"，是**已经在跑、已经在付钱的东西**。
   $75B 的客户预付尤其关键：**它说明至少有一部分对手方是先付钱再拿算力的**，
   这与我在 (b) 里"backlog 只值客户付得起的那部分"的怀疑正好相反。
   我把它当作缓解因素处理了，但没有给它足够权重——因为我拿不到分客户的拆分。

2. **价格已经做了大部分工作，而我的 base 情景可能过于苛刻。**
   base 用 11.8% 的十年 OE CAGR，而管理层指引是收入 CAGR 31% / EPS CAGR 28% 到 FY2030，
   FY2027 收入指引就是 +34%。我把管理层指引砍掉了一大半。
   如果只砍掉三分之一，base IRR 就过 8% 了。**"跌了 56% 之后我还要求 base 过 8%"这件事本身，
   在概率上可能是过度保守**——卖方 43 人共识目标价 $259（区间 $155–400），**没有一个人的目标价低于现价**。
   我与整个卖方共识的分歧幅度（−45%）需要一个比"我更谨慎"更强的理由，而我并没有。

3. **最不舒服的一条：我可能在用"结局已知"来倒推证据。**
   这张卡的选题理由就是"市场已经否决了 ORCL"。
   一旦带着这个前提去读财报，$4,599M 的利息、5.22x 的杠杆、11.24% 的 ROIC
   都会自动排成一条通向坏结局的线。但**同样这组数字，如果股价在 $300**，
   我很可能会写成"重投资期的正常特征"——就像本库的 AMZN 卡当初对 $200B capex 所做的那样。
   **对照实验的价值来自于结局已知，而它的危险也来自于结局已知。**

**但我仍然维持 WATCH / 0%，原因收敛到一条**：不是价格，不是生意质量，
而是 **>50% 的 RPO 押在一个我完全没有财务数据的私营交易对手上，而 Oracle 自己也不点名**（O1）。
Oracle 用**投资级公司债的确定负债**去承接**一个未上市公司的八年期承诺**——
这个错配的下限我算不出来，而 bear 情景 −8.9% 是**带 $124B 净债务**的 −8.9%，不是可以坐等回归的那种下跌。
**在 O1 关闭之前，正确的仓位是 0，不是小。**
这与 AMZN 卡的处理一致（"owner earnings 桥不闭合 → 不建仓"），但 ORCL 多了一层：AMZN 的桥不闭合是**算不清**，
ORCL 的桥不闭合是**算不清 + 借钱去赌**。
