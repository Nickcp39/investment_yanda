# SNOW — 生意模型

## 1. 钱是怎么进来的
**Consumption（用量）计费**，不是席位制。客户预付 credit，按实际计算/存储用量消耗。
收入 = 客户跑了多少查询、存了多少数据、调了多少次模型。

这带来三个与席位制 SaaS **结构不同**的性质：

| 性质 | 后果 |
|---|---|
| 收入随客户工作负载波动 | **季度收入天然波动**，指引比席位制难做 |
| 不需要「卖出更多座位」就能增长 | NRR 125–126% 主要来自**存量客户用得更多** |
| 客户降本时**立刻**反映在收入上 | 没有年度合同做缓冲；下行传导比席位制**更快** |

## 2. 增长的三层

```
第一层 存量客户用量自然增长   → NRR 125-126%（主引擎）
第二层 大客户数量增长          → TTM>$1M 客户 733 → 779 (+29%)
第三层 新产品带来的新工作负载  → Cortex / Cortex Code（AI 层）
```

FY2027 指引从 +27% 上调到 +31%，公司点名的驱动是**第三层的 Cortex Code**。

## 3. 关键结构性事实：增长越快，毛利越薄

| | 核心平台（存储/查询） | AI 产品（推理/GPU） |
|---|---|---|
| 毛利率 | 高 | **明确低于核心平台**（公司自述） |
| 成本性质 | 第三方云基础设施 | **第三方云基础设施 + GPU** |

产品毛利率已从 **76% → 75%**。管理层承诺 FY2027 守住 75%，
**方式是拿 AWS 合同下更低的带宽成本去抵消**。

> ⚠️ **这个抵消是不对称的。**
> 带宽议价是**一次性的存量让利**；AI 负载占比是**持续上升的结构变化**。
> 用前者抵后者，能撑一到两年，撑不了十年。
> **这是本卡最重要的一条机制判断，且它不需要任何未披露数据就能成立。**

## 4. 与本库既有 SaaS 的对照

| | ADBE / INTU（席位制） | **SNOW（consumption）** |
|---|---|---|
| AI 的威胁 | AI 替代**用户**（少雇人 → 少买座位） | AI **创造**工作负载（更多推理 → 更多用量） |
| AI 的机会 | 涨价/加新 SKU | 新负载直接变收入 |
| **AI 的隐藏成本** | 几乎没有（软件毛利不变） | **毛利率被 GPU 稀释** |
| 下行传导速度 | 慢（年度合同） | **快（用量即时）** |

> 结论：**SNOW 在 AI 叙事里站在需求的正确一侧，但站在成本结构的错误一侧。**
> 席位制 SaaS 怕的是「客户不需要我了」；SNOW 怕的是「客户需要我，但我赚不到钱」。
> **这是两个完全不同的风险，不能用同一条分界线处理** —— 直接回应批次 T1。
