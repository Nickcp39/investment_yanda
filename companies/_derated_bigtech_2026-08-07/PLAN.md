## 1. 本批要回答的 thesis（每家必答）

> 一只股票跌了 45–62%，**崩的是倍数还是生意**？
> 这个问题本库在 BSX 上已经答过一次（"崩的是倍数不是生意"，EV/EBITDA 35x→16x），
> 本批要把它从**一次直觉判断**升级成**可复用的定量分解程序**。

每个 Runner 除常规 M1–M6 外，**必须显式**：

1. **把跌幅拆成两项**：(i) 倍数压缩 (ii) 盈利/FCF 基数变化。给算术，不给叙事。
2. **点名 owner-earnings 锚并做敏感性**。本库有一个跨卡的系统病：
   META 卡自己写明 FCF锚→base IRR ~0%、中点→+4%、经营NI锚→+10%——
   **同一家公司换个锚就跨过 8% 门槛**。每家必须像 META 那样把锚敏感性摆出来。
3. **AI 替代机制要具体到产品层**，不许泛泛而谈"AI 冲击"。哪个产品、哪一层、
   可证伪的指标是什么。
4. **护城河做 BSX 式检验**：哪部分是**结构性锁定**（封住品类的专利、真实切换成本、
   网络效应），哪部分只是**在位惯性**。本库标准教训：先发优势无结构锁定 → 侵蚀极快。

### INC-002：批次因 sub-agent 扇出耗尽 session 限额而集体中断（2026-08-07）

**现象**：4 个 runner 各自再 spawn 子 agent 做取数（ADBE 的 ARR 史、INTU 的
Direct File 政策、NFLX 的收视份额、软件可比公司倍数），**7 个 agent 并发**
在约 14:00 EDT 撞上 session 限额，全部 `terminated early`，14:30 重置。

**损失评估**：磁盘上活下来的是各家 `facts.md` + `raw/` 抽取（INTU 最完整，
4 份 SEC 原文共 ~82KB）。**真正的损失是只存在于 transcript 里、尚未落盘的
中间成果**——最典型的是 ADBE 子 agent 已交付的"完整 net-new ARR 历史序列"，
而 ARR 恰恰是该家最可证伪的单一指标。

**教训（写进后续批次铁律）**：
1. **runner 禁止再 spawn 子 agent**。批量批次里每多一层扇出，并发就乘一次，
   限额是全局共享的——一家超支会连坐整批。
2. **先落盘再分析**。取到的原始数据必须**立刻**写进 `raw/`，不要攒到写
   dossier 时再一次性输出。transcript 不是持久化存储。
3. **写入优先级要预先声明**：`raw/` → `decision_card` → 核心命题模块 →
   其余。这样中断发生在任何一点，磁盘上都是"最有价值的那部分先在"。

**处置**：未重开新 agent（会重做全部取数），而是用 SendMessage 从各自
transcript **原地恢复**，并下达上述三条 + 收窄范围（"用已有数据写，
缺的进 OPEN 封完整度，不要再做网络研究"）。

> **预期**：不预设结论。但基于 mega7 的经验，若四家全 WATCH，本批价值在于
> **用一手数据把"跌了 50% 还是不够便宜"这件事量化**；若出现 STARTER，
> 它将是本库第二个 `binding_constraint ≠ 价格` 的样本（第一个是 MSFT）。
