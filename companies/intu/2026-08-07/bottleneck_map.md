# INTU Bottleneck Map — as_of 2026-08-06

**问题**：如果一个 AI agent 想抢走 Intuit 的生意，它会在**哪一步卡住**？
这份地图把每条腿拆成"AI 能做的"和"AI 必须绕过的关口"。

> **诚实标注**：本图中关于 IRS e-file 授权机制（Authorized e-File Provider / EFIN / MeF / Form 8879）
> 的具体门槛，本轮**未从 irs.gov 一手核实**（OPEN **O9**）。它们在这里是**推理，不是引证**。
> 这是本 dossier 最重要的单个证据缺口，因为它是 TurboTax 护城河论证的支点。

---

## 1. TurboTax：AI 卡在哪？

| 步骤 | AI 能做吗 | 真正的瓶颈 |
|---|---|---|
| 读 W-2/1099，理解税法 | **能，而且便宜。** Goldman 估：AI 处理一份标准个税边际成本约 **$0.12**，vs TurboTax 收最高 **$162** | — |
| 算出应纳税额 | **能** | — |
| **把申报表报送给 IRS** | **不能直接做** | 需要 **Authorized e-File Provider** 资质 + **EFIN** + 接入 **MeF** 报送系统。这是一个**牌照关口**，不是技术关口 |
| 50 个州的州税 | 理论上能，工程上很贵 | 50 套独立规则 + 各州自己的报送通道 |
| **算错了谁赔** | **不能承担** | 准确性担保 + 稽核代表责任。一个模型不能签字、不能上稽核庭、不能赔钱 |
| **让用户知道你存在** | **不能靠模型解决** | 每年八九位数的获客广告 + 品牌信任。报税是一年一次的高恐惧决策 |

**结论**：AI 已经解决了"算税"，还没有解决"**报送 + 担责 + 获客**"。
但注意三点削弱：
1. **牌照关口不高**。EFIN 是可申请的，Cash App Taxes、FreeTaxUSA 早就拿到了。它挡得住随手写的 LLM wrapper，挡不住一家认真做产品的公司。
2. **Intuit 自己在主动让出低端**（pay-nothing 800 万 → 700 万）。**关口再高，你自己开门放人走，墙就没意义了。**
3. **护城河已经搬到了"专家网络"上**（TurboTax Live 占 TurboTax 收入 53%）。专家的成本结构正是 AI 最直接的攻击面。

→ **瓶颈真实存在，但它正在从"结构性"退化为"运营性"。**

## 2. QuickBooks / GBS：AI 卡在哪？（这里才是真墙）

| 步骤 | AI 能做吗 | 真正的瓶颈 |
|---|---|---|
| 做一个更好的记账界面 | **完全能** | — |
| 自动分类交易、生成报表 | **完全能，而且可能比 QuickBooks 好** | — |
| **拿到银行/信用卡的交易数据** | 需要接管道 | 直连协议 + 多年的**对账历史**。新玩家能拿到今天的流水，拿不到过去七年的对账线索 |
| **代缴 50 州薪资税** | **不能** | Intuit 是 **registered agent**，替客户向 50 个州申报并汇缴薪资税。这是**牌照 + 运营 + 责任**三重关口 |
| **处理收款** | **不能** | money transmitter 牌照（各州分别申领）+ 风控 + 结算 |
| **用现金流做放贷** | 不能 | QuickBooks Capital 的风控数据来自它自己的账套——**这是数据飞轮，不是软件功能** |
| **让会计师推荐你** | **不能** | 约 **100 万**会计师。会计师不换客户的账套——重训成本、事务所标准化、责任风险 |
| **让客户搬家** | 不能 | 迁移 = 历史交易 + 对账记录 + 薪资历史 + 税务归档。**审计级的痛。** |

**结论**：QuickBooks 的价值 **95% 不在界面上**。
AI 可以做出一个更好的记账 UI，然后发现自己需要：50 个州的薪资税资质、支付牌照、
七年的对账历史、和 100 万个不想改流程的会计师。

**数据佐证（零裂缝）**：9M FY2026 QBO Accounting **+24%**、Online Ecosystem **+20%**、
FY2025 ARPC **+14%**、付费客户 **+5%**、中端市场 **+38%**、线上支付额 **+30%**。

## 3. Credit Karma：AI 卡在哪？

**卡不住，但也不需要卡——因为它的瓶颈根本不是 AI。**

| 瓶颈 | 性质 |
|---|---|
| 1.4 亿会员的信用档案 | 数据资产，AI 不替代 |
| 与发卡行/贷款商的撮合关系 | 商务关系，AI 不替代 |
| **放贷方的风险胃口** | **纯周期变量——这才是真瓶颈** |

FY2023 已经演示：信贷收紧 → 收入 **−9%**、分部营业利润 **−19%**。
→ **给这条腿的折价应该来自周期贝塔，不是 AI 贝塔。**

---

## 4. Mailchimp：AI 卡在哪？

**几乎无处可卡。**

| 步骤 | 瓶颈 |
|---|---|
| 写营销文案 | 无。LLM 最强场景 |
| 设计邮件序列 | 无 |
| 发邮件 | 送达率/IP 声誉——有一点，但可外购 |
| **换供应商** | **导出联系人 CSV。** 没了 |

**这就是为什么四条腿里只有 Mailchimp 已经在下滑。**
它是这个组合里唯一一个"价值全在界面和内容生成上"的业务。
**Mailchimp 不是 AI 论述的反例，它是 AI 论述唯一被证实的样本——
而它只占约 7% 的收入。**

## 5. 汇总：瓶颈强度排序

| 腿 | 瓶颈强度 | 瓶颈类型 | 趋势 |
|---|:--:|---|---|
| QuickBooks / GBS | **强** | 牌照 + 数据历史 + 渠道 + 迁移成本 | **稳定** |
| ProTax | 中强 | 专业工作流锁定 + 报税师执照 | 稳定但不增长（+4%） |
| TurboTax | **中，且在下降** | 报送资质 + 担责 + 获客 → 正退化为专家网络运营 | **下降** |
| Credit Karma | 中 | 数据 + 商务关系（但受制于信贷周期） | 周期 |
| Mailchimp | **弱** | 基本没有 | **已失守** |

> **投资含义**：市场给了整个公司一个"瓶颈已失守"的估值（13.5x 前瞻 EPS），
> 但按利润池加权，**约 60% 的利润坐在"强瓶颈且稳定"的那条腿上**。
> 这个错配就是本 dossier 的 M6 给 +1 的原因。
